# Lumino Zapier Course Webhook Integration

This document describes how to configure Zapier to forward Lumino payments to the application webhook endpoint to automatically enroll clients into purchased courses.

---

## 1. Webhook Endpoint Details

- **URL**: `https://<YOUR_APP_DOMAIN>/api/webhooks/lumino`
- **Method**: `POST`
- **Content-Type**: `application/json`

---

## 2. Authentication

The webhook requires an HTTP Authorization header containing a shared Bearer token:

```http
Authorization: Bearer <LUMINO_ZAPIER_WEBHOOK_SECRET>
```

### Environment Variable

Configure the shared secret in your environment variables (`.env.local` / deployment environment):

```bash
LUMINO_ZAPIER_WEBHOOK_SECRET=your-secure-random-secret-key-here
```

---

## 3. Zapier Request Body Format

Zapier must send a JSON payload containing the following fields:

```json
{
  "customerEmail": "customer@example.com",
  "customerName": "John Doe",
  "paymentAmount": "$1,139.84",
  "paymentCreatedAt": "2026-08-07T20:07:09.870Z",
  "paymentCurrency": "USD",
  "paymentId": "4277a5b8-4f7f-4be5-a13e-7820e504867e",
  "paymentMethod": "visa_applepay",
  "paymentStatus": "Succeeded",
  "courseId": "COURSE_DOCUMENT_ID"
}
```

> **Note**: Both a flat JSON body or a nested `{ "body": { ... } }` wrapper (often generated by n8n or Zapier webhook triggers) are supported.

### Field Definitions

| Field              | Type               | Required | Description                                                                                                  |
| ------------------ | ------------------ | -------- | ------------------------------------------------------------------------------------------------------------ |
| `customerEmail`    | `string`           | **Yes**  | The client's email address used to locate their user account. Case-insensitive and trimmed.                  |
| `paymentId`        | `string`           | **Yes**  | Unique transaction identifier from Lumino/payment processor (used for deduplication).                        |
| `paymentStatus`    | `string`           | **Yes**  | Status of payment. Only `"Succeeded"` (case-insensitive) triggers enrollment.                                |
| `courseId`         | `string`           | No       | Optional. Specific course ID. If omitted, automatically resolves published course(s) configured with Lumino. |
| `customerName`     | `string`           | No       | Full name of the customer from checkout.                                                                     |
| `paymentAmount`    | `string \| number` | No       | Total amount charged (e.g., `"$1,139.84"` or `1139.84`).                                                     |
| `paymentCreatedAt` | `string`           | No       | ISO timestamp of when the payment was created.                                                               |
| `paymentCurrency`  | `string`           | No       | Currency code (default: `"USD"`).                                                                            |
| `paymentId`        | `string`           | **Yes**  | Unique transaction identifier from Lumino/payment processor (used for deduplication).                        |
| `paymentMethod`    | `string`           | No       | Method used (e.g., `"visa_applepay"`, `"card"`).                                                             |
| `paymentStatus`    | `string`           | **Yes**  | Status of payment. Only `"Succeeded"` (case-insensitive) triggers enrollment.                                |

---

## 4. Processing & Enrollment Logic

1. **Authentication**: Checks the `Authorization: Bearer <token>` against `LUMINO_ZAPIER_WEBHOOK_SECRET` using a constant-time comparison.
2. **Audit Logging**: Logs every incoming webhook payload into the `lumino-webhook-events` Firestore collection.
3. **Status Check**:
   - If `paymentStatus` is **NOT** `"Succeeded"`, the webhook acknowledges the event with `200 OK` and skips enrollment without error.
4. **Customer Lookup**:
   - Searches for the user in the `user` collection by normalized `customerEmail`.
   - Falls back to Firebase Auth lookup if not indexed directly.
   - If no user is found, returns **`404 Not Found`** so Zapier knows to retry (e.g. if the user account is created slightly after payment).
5. **Course Lookup**:
   - Finds the course by `courseId` in Firestore.
   - If course does not exist, returns **`404 Not Found`**.
   - If course is unpublished, returns **`422 Unprocessable Entity`**.
6. **Atomic Transaction & Deduplication**:
   - Uses `paymentId` as the document ID in `user-lumino-payments`.
   - If `paymentId` has already been recorded (duplicate webhook delivery), returns `200 OK` (`duplicate: true`) immediately without creating duplicate enrollments.
   - If new, creates a `user-course-enrollment` document and atomically increments `enrolledStudentsCount` on the course document.

---

## 5. HTTP Response Codes

| Status Code          | Reason                                                                                                | Zapier Action                                |
| -------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `200 OK`             | Payment processed and user enrolled (or duplicate delivery acknowledged)                              | Success, no retry                            |
| `400 Bad Request`    | Malformed JSON or missing required fields (`courseId`, `customerEmail`, `paymentId`, `paymentStatus`) | Fix Zapier payload mapping                   |
| `401 Unauthorized`   | Missing or invalid Bearer token                                                                       | Check `Authorization` header in Zapier       |
| `404 Not Found`      | Client email or courseId not found in the database                                                    | Zapier retries until user account is created |
| `422 Unprocessable`  | Course exists but is not published                                                                    | Publish course or fix courseId               |
| `500 Internal Error` | Unexpected Firestore or server failure                                                                | Zapier retries                               |
